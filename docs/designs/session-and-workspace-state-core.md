## Problem Statement

RayuCode serves 20,000+ users across Desktop (`desktop/`) and the VS Code extension (`vscode/`), both talking to the same Rust daemon (`crates/rayucode-harness-api-server`). Because the session and workspace state layer was copy-pasted and patched independently across both surfaces, four live reliability failures hit users daily:

1. **Duplicate chats in the sidebar:** Desktop defaults `showProjectChatsInRecents` to `true` (`desktop/src/components/shell/sidebar-projects-pane.tsx`) and merges stale `desktop-sessions.json` entries back into daemon lists (`desktop/src/lib/ipc-client.ts`). VS Code matches `!s.workingDir` inside every folder loop (`vscode/webview/src/features/shell/components/SidebarProjectsPane.tsx`) and eagerly calls `sessions.create` on every New Chat click, spawning duplicate empty `"Untitled session"` rows.
2. **Broken project creation and fragmented persistence:** Desktop generates random `proj_<slug>_<ts>` IDs without `fs.realpath` canonicalization (`create-project-dialog.tsx`), halts auto-discovery once any project exists, and splits active workspace state across 3 disconnected stores. VS Code stores pins and archives in `workspaceState` with raw string matching, completely disconnected from Desktop's `desktop-sidebar.json`.
3. **Duplicate user prompt bubbles in chat:** Both `desktop/src/features/execution-trace/components/chat-stream.tsx` and `vscode/webview/src/features/chat/hooks/useChatStream.ts` append `liveTurn` onto `fetchedTurns` comparing only `t.id === liveTurn.id` (`hist_<sid>_1` vs `live_turn_<ts>_1`), rendering the prompt twice when history loads right after submission (once as a fake empty completed turn, once spinning).
4. **Frozen spinners and killed background tasks on chat switch:** Both `desktop/src/lib/harness-adapter.ts` and `vscode/webview/src/lib/harness-adapter.ts` omit `case "error":` in `mapHarnessFrameToLiveEvents`, dropping error frames into `default: return []` and leaving `Working · 5m 8s` stuck forever. In VS Code, `vscode/host/runtime/sessionHub.ts` holds a single `this.sessionClient` and calls `previous.close()` on every `attachSession` or `createSession`, killing any running task's event stream the moment a user opens or switches chats (whereas `desktop/electron/daemon-client.ts` already added a 6-socket pool). Neither surface invalidates `["chat", "history", sessionId]` on `turn_done` or reconciles stale `liveTurn` state against `session.status === "idle"` on attach.

## Demand Evidence

- Established product with 20,000+ active users across Desktop and VS Code.
- Reproduced directly in Extension Development Host screenshots (`uploaded_media_1795601607006.jpg`: duplicate user prompt + `Working · 5m 8s` stuck spinner; `uploaded_media_1795601682006.jpg`: active run frozen with active stop button after switching to a new chat).

## Status Quo

Users bounce between Desktop and VS Code on the same repositories, seeing duplicated sessions across Projects and Recents, disappearing projects, empty `"Untitled session"` rows, doubled user bubbles, and broken background runs whenever they open a second chat in VS Code. Every state bug fix currently has to be manually re-implemented in two ~3,500-line diverged TypeScript stacks.

## Target User & Narrowest Wedge

- **Target user:** Active RayuCode developers using Desktop and/or the VS Code extension across multi-repo workspaces.
- **Narrowest wedge (Wave 1):** Extract one shared workspace package `@rayu-dev/rayucode-session-core` (`packages/session-core`, already matched by `pnpm-workspace.yaml`) with `/host` and `/client` sub-exports, and wire both `desktop/` and `vscode/` to it. Defer shared React UI component extraction (`packages/chat-ui`) to a follow-up wave.

## Constraints

- Zero Rust daemon protocol breaks in Wave 1: Desktop and VS Code must ship against the existing Harness API v1.14 NDJSON socket without requiring a simultaneous CLI/daemon release.
- Packaging compatibility: `packages/session-core` must compile to ESM (`dist/*.js` + `dist/*.d.ts`) matching `packages/ui`'s layout so `desktop`'s `tsc -p tsconfig.electron.json` + `electron-builder` (`app.asar`) and `vscode`'s `esbuild` (CJS host bundle) + `vite` (webview bundle) both consume it cleanly.
- Desktop UI rules (`DESIGN.md`, `desktop/src/styles/globals.css`, `pnpm verify`) and VS Code `pnpm build && pnpm test` must remain green with zero raw hex values or design-token regressions.
- Non-destructive migration: Existing Desktop (`desktop-sidebar.json`, `desktop-sessions.json`) and VS Code (`workspaceState` pins/archives) data must migrate cleanly on first load into `~/.rayu/workspaces.json` without losing user pins, archives, or registered projects.

## Premises

1. **One canonical workspace and pin/archive ledger (`~/.rayu/workspaces.json`):** Deduplicated by `fs.realpath`, explicit validated `sessionIds` membership, mutually exclusive global `pinnedSessionIds` and `archivedSessionIds` (preserving archive order for unarchive), serialized atomic writes (`tmp` + `rename` + cross-process lock/reload). VS Code defaults to displaying currently open workspace folders in the sidebar with an "All Projects" scope toggle, while sharing canonical pins, archives, and realpath identity with Desktop.
2. **Strict disjoint sidebar tree and reused provisional blank session:** Pure derivation (`deriveSidebarTree`) guarantees every session renders in at most one group (its owning workspace or Ungrouped), never duplicated into Recents (flat chronological list is a separate view mode toggle). Clicking New Chat reuses one provisional blank session per workspace (coalesced on rapid clicks) instead of eagerly creating empty `"Untitled session"` rows.
3. **Resident per-session socket pool in shared host core:** Lift `desktop/electron/daemon-client.ts`'s `sessionClients` pool (`activeTurnSessions` and pending-interaction sessions protected from eviction; bounded LRU eviction for idle sessions) into `@rayu-dev/rayucode-session-core/host`, replacing `vscode/host/runtime/sessionHub.ts`'s single-socket model so switching chats or opening New Chat never interrupts a running stream.
4. **Shared client stream adapter and unified turn reconciler:** Extract `harness-adapter`, `liveTraceStore`, and turn-history reconciliation into `@rayu-dev/rayucode-session-core/client`. Optimistic user prompt bubbles carry a local submission marker and retire as soon as durable history contains the matching turn; `ev: "error"`, `turn_stopped`, and socket close settle active turns deterministically; `turn_done`/`turn_stopped` invalidate history queries; attach/focus reconciles stale `liveTurn` against `session.status === "idle"`. Also fix minor `vrayu-harness-api...` version prefix display in the top bar.

## Approaches Considered

### Approach A: Shared `@rayu-dev/rayucode-session-core` (`/host` + `/client`) [Selected]
Extract host state (`WorkspaceRegistry`, `SessionSocketPool`) and client state (`deriveSidebarTree`, `harness-adapter`, `liveTraceStore`, `reconcileChatTurns`) into `packages/session-core`, consumed by both `desktop/` and `vscode/`. Stops drift immediately with zero Rust daemon protocol changes.

### Approach B: Minimal viable in-place patches in `desktop/` and `vscode/` [Rejected]
Rejected: faster short-term patch, but leaves ~3,500 lines of state, adapter, and socket logic duplicated across both apps, repeating the exact drift that left VS Code without Desktop's socket pool.

### Approach C: Rust daemon-owned `WorkspaceRegistry` + TS `packages/session-core/client` [Deferred]
Deferred: putting `WorkspaceRegistry` behind Harness API v1.15 RPCs would eliminate cross-process file locking on `~/.rayu/workspaces.json` and expose projects to CLI, but requires Rust + SDK + daemon rollout. Keeping `WorkspaceRegistry` behind an async interface in `packages/session-core/host` lets us swap the persistence backend to Rust daemon RPCs in a later wave without touching either frontend.

## Recommended Approach

Build `@rayu-dev/rayucode-session-core` with two strictly separated entry points:

- **`@rayu-dev/rayucode-session-core/host` (Node.js only):**
  - `WorkspaceRegistry`: canonical `fs.realpath` identity, idempotent `register(path)` / `ensureWorkspace(path)`, explicit `attachSession(workspaceId, sessionId)`, mutually exclusive `pinSession` / `archiveSession`, serialized mutation queue, atomic file writes with cross-process lock + external mtime/watch reload, one-time migration from legacy Desktop/VS Code stores.
  - `SessionSocketPool`: per-session `RayucodeClient` map, `activeTurnSessions` + `pendingPermissionSessions` pinned against eviction, bounded LRU eviction (default max 6) for idle sessions only, serialized attach/create transitions, clean error propagation with guaranteed `session_id`.
- **`@rayu-dev/rayucode-session-core/client` (Browser / Renderer safe, zero Node imports):**
  - `deriveSidebarTree(input)`: pure deterministic grouping (`WorkspaceGroup[]`, `ungrouped`, `pinned`, `archived`, optional `scopePaths` filter for VS Code open folders, flat chronological view mode, single visible provisional blank session rule).
  - `mapHarnessFrameToLiveEvents` + `HarnessStreamTracker`: single canonical adapter handling `ev: "error"`, `turn_stopped`, `turn_done`, `tool_*`, `permission_request`, `file_changes_state`, `provider_guardrail`, and socket-disconnect synthesis.
  - `createLiveTraceStore` + `reconcileChatTurns(historyTurns, liveTurn, sessionStatus)`: unified timeline merger that deduplicates optimistic user prompts against loaded history by normalized prompt/turn watermark, clears stale running state when `session.status === "idle"`, and exposes callbacks for host query invalidation (`["chat", "history", sessionId]`, `["sessions"]`).

Thin host wrappers remain in `desktop/electron/` (IPC bridge, desktop tools, Electron window/storage wiring) and `vscode/host/` (Webview RPC bridge, open workspace folders, native editor/diff APIs).

## Success Criteria

1. **Zero duplicate sidebar rows:** A session assigned to a project appears once in grouped view; flat Recents is a separate view mode; clicking New Chat 5 times rapidly produces at most 1 blank session per workspace.
2. **Idempotent canonical projects:** Adding the same directory via symlink, trailing slash, or mixed case resolves to the same workspace record in `~/.rayu/workspaces.json`; Desktop and VS Code reflect pins/archives/projects consistently without clobbering each other.
3. **Zero duplicate user bubbles:** Submitting from Home or inside an active chat never renders the user prompt twice when `sessions.history` resolves.
4. **Resilient background streaming and error settlement:** Starting a task in Chat A, switching to New Chat or Chat B, and returning to Chat A preserves live tool progress and working Stop control in both Desktop and VS Code. Any daemon `ev: "error"` or socket close settles the turn within 1s with visible error feedback (never stuck at `Working · 5m 8s`).
5. **All verification gates pass:** `packages/session-core` unit tests, `cd desktop && pnpm verify`, and `cd vscode && pnpm build && pnpm test` pass with 0 errors.
