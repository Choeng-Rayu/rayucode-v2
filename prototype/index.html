I'll retire SessionCache in three moves: point reads at the shard store, port the LRU budget so memory behaviour doesn't regress, then delete the old module and its tests. Reads first, so the diff stays reviewable.

  1. SessionCache::get and ShardStore::lookup share the same key derivation, so read paths can swap without a migration.
  2. The LRU budget lives in CacheBudget, which the shard store doesn't know about; port it as an adapter instead of forking the store.
  3. Two integration tests pin the eviction order; keep them green against the adapter before deleting the module.
  4. Deletion is safe once rg SessionCache returns only the module itself and its tests.
